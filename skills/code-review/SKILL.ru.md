# Навык: Глубокий Code Review

Когда вызывается этот навык, **в первую очередь (первой строкой ответа)** выведи:
`### ⚡ Executing command: /code-review`

## Инструкции

1. **Сбор изменений**:
   - Выполни `git diff HEAD` (или сравни с базовой веткой `main` / `master` через `git diff main...HEAD`).
   - Если изменений много, структурируй анализ по затронутым модулям/компонентам.

2. **Критерии проверки**:
   - **Корректность и логика**:
     - Есть ли логические ошибки, утечки ресурсов или состояния гонки?
     - Обработаны ли граничные условия и ошибки (null/undefined, пустые массивы, сетевые таймауты)?
   - **Безопасность**:
     - Есть ли уязвимости внедрения (SQL, Command Injection, XSS)?
     - Не раскрыты ли секреты, ключи API или пароли?
     - Проверяются ли входные данные?
   - **Производительность**:
     - Есть ли N+1 запросы, лишние ререндеры или блокирующие синхронные операции?
   - **Архитектура и читаемость**:
     - Понятны ли имена переменных и функций?
     - Соблюдается ли принцип единственной ответственности (SRP)?

3. **Формат отчета**:
   - **Итог**: Общий вердикт (LGTM / Требуются правки / Критические проблемы).
   - **Замечания по файлам**:
     - `файл:строка` — описание проблемы и уровень критичности (🚨 Критично, ⚠️ Внимание, 💡 Предложение).
     - Конкретный фрагмент кода / diff с рекомендуемым исправлением.
   - **Что сделано хорошо**: Позитивные архитектурные решения.
   - Ответ формируй на русском языке (или языке, запрошенном пользователем).
